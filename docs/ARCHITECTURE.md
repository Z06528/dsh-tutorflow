# 架构审查与通用教学架构

本文分两部分：先按**实际源码**审 0.1.0，再说明 0.2.0 的通用教学架构。
审查结论全部来自读代码，不以 README 为准。

---

## 第一部分：0.1.0 的实际架构（审查）

### 1. 当前架构

```
index.js              宿主插件入口。注册 6 个工具、1 段系统提示、1 个运行时技能。
lib/engine.js         纯状态机 dispatch(state, action) → {state, result}。
lib/curriculum.js     两条硬编码课程 + 模式识别 + 策略表。
lib/charts.js         本地 SVG（8 种图型）。
lib/expr.js           安全表达式编译器（无 eval）。
lib/store.js          单文件 JSON，原子改名写入，按 mtime 重读。
lib/prompt.js         系统提示段正文 + 读 SKILL.md。
client.browser.js     标题栏「教学」按钮 + 正态分布滑块浮层。
skills/tutorflow/     运行时技能正文。
market/               自建格式 1 索引、awesome 提交文件。
```

数据流：模型 → 工具 → `dispatch` → 纯指令对象 → `formatCoach` 渲染成一段文字 → 模型照做。
状态落盘在 `$DSH_HOME/dsh-tutorflow/state.json`。没有自己的模型调用，没有网络。

### 2. 已经实现的功能（确实可用的部分）

- **一次一步的节奏约束**：`coach()` 只产出 `say` + `ask` 各一条，`formatCoach` 明确写「只问这一个问题」。
- **分级提示**：`light / idea / formula / solution` 四级，`reveal` 之前 `revealText` 被 `freezePublic` 清空。
- **本地图形**：函数、正态密度、分布函数、积分区域、坐标、知识结构、流程图、离散连续对照；只用 `xmlns`，无外链。
- **本地记忆**：掌握分、错题、练习历史、模式与章节，原子写入，重启可恢复。
- **插件规范**：`cordis.patch.yml`、`dsh.bundle`、`dsh.client`、`exports`、locale 元数据都在。
- **安全边界**：无 `fetch`、无境外域名、无 `eval`（`lib/expr.js` 自写递归下降解析器）。

### 3. 仍然依赖特定知识点的部分

这是 0.1.0 最核心的问题。教学能力与两条课程**在代码层耦合**，不是「默认值」而是「唯一通路」：

| 位置 | 事实 |
| --- | --- |
| `engine.js:94-112` | `isContinuousTopic(topic)` 命中才走五步课，否则落到 `generic`。 |
| `engine.js:140-146` | 分支顺序写死：`exam` → `CONTINUOUS_LESSON` → `genericAnswer`。 |
| `engine.js:148-184` | `lessonAnswer` 只读 `CONTINUOUS_LESSON.steps[stepIndex]`。 |
| `engine.js:243-330` | `openExam` / `examAnswer` 只认 `LAPLACE_EXAM`；非内置题直接给「我还不能替你把整题算完」这一句死文案。 |
| `engine.js:486-496` | `judge()` 只看 `step.signals` 与 `step.myths`——这两样只有课程包里有。 |
| `engine.js:529-542` | `currentLessonStep` / `currentAsk` 只服务 `CONTINUOUS_LESSON` 与 `LAPLACE_EXAM`。 |
| `engine.js:544-550` | `fallbackReteach` 按风格给固定句式，内容与学科无关但**与讲解无关**。 |
| `curriculum.js:15-167` | 两条课程的正文、五种讲法、提示、全解全部硬编码。 |

也就是说：**换一个知识点，讲法就没有了**。0.1.0 的「通用」只剩下一句「先别让我直接讲完」和一个「如果条件变一下哪部分会变」的通用追问。

### 4. 与通用教学目标冲突的设计

1. **关键词判对错**（`judge`）。`signals` 是子串命中。中文里「不是概率」会命中 `不是` 这种反向信号；课程包外的知识点没有 `signals`，判定只能落到默认 `partial`，学生永远过不了关。
2. **模型判定被覆盖**。工具说明写「你的判断只作参考，工具会按知识点标准覆盖明显错误」。对课程包成立，对任何其它知识点则意味着**引擎用空知识去否决模型**。
3. **模式限制自主性**。五模式里 `maxIdeas` 恒为 1，`allowFormula` 由模式决定；模型没有「这一步该怎么讲」的决定权，只能复述工具给的 `say`。
4. **`say` 是成品句子**。课程包里是准备过的讲稿；课程包外是「先别让我直接讲完。我需要知道你现在站在哪。」这类空话。模型被要求照说，于是教学内容质量被钉死在引擎的上限。
5. **记忆只有分**。`mastery` 是 `{score, attempts, wrong}`，±18/−6 地加减。一次答对 `+18` 就能接近及格；没有证据条数、没有跨会话、没有遗忘曲线、没有错误类型。
6. **没有路线概念**。`stepIndex` 只对硬编码课程有意义；陌生知识点没有「先讲什么、后讲什么」的结构。
7. **可视化偏科**。8 种图型里 5 种是概率论形状（正态、分布函数、积分区域、离散连续对照），无法支撑统计之外的学科。
8. **客户端偏科**。标题栏浮层是一张正态分布演示图，与新定位无关。

### 5. 必须修改的文件

| 文件 | 处理 |
| --- | --- |
| `lib/engine.js` | 重写。状态机改为「分类 → 路线 → 动作 → 证据 → 记忆」。 |
| `lib/curriculum.js` | 降级为兼容层（旧导出名 → 新模块）。 |

| `lib/charts.js` | 增加跨学科图型。 |
| `lib/store.js` | 增加 v1→v2 迁移。 |
| `client.browser.js` | 改为通用本地绘图面板。 |

### 6. 可以保留的模块（一行不改或只加不删）

- `lib/expr.js`：安全、无 `eval`、已够用。
- `lib/store.js` 的原子写入与 mtime 缓存策略。
- `lib/charts.js` 的画布、坐标轴、`pathFrom`、`esc`、`frame` 等基础设施与全部原有图型。
- `cordis.patch.yml`、`package.json` 的 `dsh.bundle` / `dsh.client` / `engines` / `peerDependencies`。
- `client.browser.js` 的 `window.__ModuleLoader__.load` 注册方式与 `conversation.session.header.actions` 插槽用法。
- `bin` 无、构建无——「零构建、纯 ESM」这个特性必须保住。
- 两条课程的全部文字内容：迁进 `lib/packs/probability.js`，一个字没删。

## 第二部分：0.2.0 通用教学架构

### 一句话

**模型负责内容，引擎负责形状。**

引擎永远不知道「矩阵的特征值」是什么，但它知道：这类问题该先定位再下定义、一个知识点只能问一个问题、
同一个讲法不能用两次、答错要先分型、答对一次不能算过。这些和学科无关，所以对任何知识点都成立。

### 分层

```
lib/taxonomy.js   分类：意图 / 知识类型 / 学科 / 复杂度 / 起点     （纯启发式，零课程）
lib/moves.js      动作：表征轮换、错误分型、追问框架、模式策略     （零课程）
lib/plan.js       路线：通用骨架 + 模型自拟路线的形状校验          （零课程）
lib/mastery.js    记忆：证据、置信度、掌握状态、间隔复习           （零课程）
lib/engine.js     状态机：把上面四层拼成一次教学动作
lib/packs/        可选课程包：更成熟的内容种子（不是前提）
```

依赖方向是单向的：`engine → taxonomy/moves/plan/mastery`，`engine → packs`（可选）。
删掉 `lib/packs` 整个目录，插件仍然能教任何知识点，只是概率论那两条课会走通用路线。

### 1. 如何识别用户的学习需求

`classify()` 同时对意图与知识类型打分，不取第一个正则命中：

- **意图**：`learn / quick / exam / review / explore / chat`。`quick` 与 `learn` 同时命中时判 `quick`——**不把想要快速答案的人拉进课堂**。
- **知识类型**：`concept / principle / procedure / code / math / data / open / fact / skill / mixed`。它只决定路线的**形状**。
- **两条纠偏规则**（都来自实际误判）：
  - 「什么是矩阵的特征值」带数学词，但**不是题**，所以走 `concept` 而不是解题路线；
  - 含「定理 / 定律 / 为什么 / 机制」且不是题，走 `principle`。
- **复杂度 1–5**：按长度、是否含证明/推导/多问、是否是题递增。
- **起点**：`beginner / partial / advanced / unknown`，显式话术优先（「没学过」）。

模型可以用 `intent` / `knowledgeType` / `subject` / `level` 参数**覆盖**任何一项。
启发式只是兜底，不是权威。

### 2. 如何自主制定教学计划

两层，任何一层单独都能工作：

1. **引擎骨架**（不需要课程库）：按知识类型生成 3–4 步，例如
   - 概念：直觉锚点 → 说明边界 → 连接到已知 → 换条件确认
   - 原理：固定现象 → 拆因果链 → 关键条件 → 反事实验证
   - 代码：心智模型 → 最小例子 → 逐层追踪 → 改一个变体
   - 数学：分清已知所求 → 关键关系 → 分步推导 → 验算迁移
   - 开放：澄清边界 → 多种解释 → 证据要求 → 可被推翻的综合
2. **模型自拟**：`tutorflow_plan` 提交 3–8 步，每步「概念名 + 一道检查题」。
   引擎只校验**形状**（步数、概念不重复、每题一问），不校验内容；通过后接管骨架。

关键点：骨架先给，模型后改。**弱模型不写路线也能教；强模型可以写得更贴合内容。**

### 3. 如何根据回答调整教学策略

判定（`verdict`）与错误类型（`errorType`）由**模型**给出——它懂内容；引擎把它翻译成动作：

| 情况 | 动作 |
| --- | --- |
| `unclear` | `probe`：换个更具体的问题把思路逼出来，不放行 |
| `incorrect`（第一次） | `reteach`：**换一种表征**重讲，然后重问同一个检查点 |
| `incorrect`（连续第二次） | `simplify`：把问题缩到最小可判断的一问，先拿回一次成功 |
| `partial` | `narrow`：只补缺口，不重讲已经对的部分 |
| `correct`（证据不够） | `verify`：换条件再确认，不推进 |
| `correct`（证据够） | `advance`：进入下一步 |

模型不给判定时，引擎**绝不默认答对**：只做「不知道→unclear」「带问号→unclear」「其余→partial」三种保守推断，
于是最坏情况是继续追问，而不是放行。

错误类型决定补法，这是 0.1.0 完全没有的东西：

- `concept` → 可指认的例子与反例，不要用更抽象的话再讲一遍
- `procedure` → 把方法压成两步，只做第一步
- `computation` → 概念别重讲，只把出错那一行拆开
- `reading` → 复述已知与所求
- `recall` → 给提取线索，不要重推
- `expression` → 给一个句式让他填

### 4. 如何处理没有预设课程的知识点

这是验收线。走这条路：

`classify` → `scaffoldPlan`（按知识类型）→ 一次诊断（需要时）→ 逐步讲解 → 每题记证据 → 收口排复习。

全程不查任何课程表。课程包只在命中时**替换掉第一步的种子文本与误区句式**，命中不了就走上面这条，
`plan.source` 记为 `scaffold`，工具返回里 `路线` 一行写的就是这条骨架。

### 5. 如何处理开放式问题

`knowledgeType === 'open'`（或带「为什么 / 该不该 / 哪个更好」且不是题）走多视角路线：
澄清边界 → 至少两种解释 → 各自需要什么证据 → 给出可被推翻的判断。
检查题不问「对不对」，问「你现在的判断需要看到什么证据才会改变」。
判定用 rubric 语义（是否给出了机制、是否区分了证据与结论），不用标准答案。

### 6. 如何进行语义判断与理解检验

三件事分开：

- **语义判断**交给模型（它读得懂学生的话），但要求结构化输出 `verdict + errorType + evidence`。
- **教学决策**由引擎做（确定性、可测、不受模型心情影响）。
- **掌握判断**由证据累积做：一次答对只让置信度升到约 0.2–0.3，`status` 最多到 `introduced`；
  要 `mastered` 必须 4 条以上证据、分数 ≥85、**跨两天到场**、并且至少完成一次到期复习。

课程包是唯一例外：`myths` 命中直接判错（因为它比模型的即时判断更准），但只对课程包自己的步骤生效。

### 7. 如何调用图形、公式与其他工具

- 图：`tutorflow_plot` 14 种图型（原 8 种 + 柱状、多曲线、表格、结构树、时间线、代码追踪）。
  引擎只在表征是「图形」且确实需要时给 `chartSuggestion`，避免为画图而画图。
- 公式：不引入 MathJax/KaTeX（会带来外部资源与体积），用纯文本关系式；`formula` 级提示只给关系式不给最终结果。
- 代码：`code` 图型给「逐行 + 该行发生了什么」的执行追踪。

### 8. 学习记忆

`mastery` 每条记录：`score / confidence / evidence / correct / partial / wrong / errors{} / days[] / ease / intervalDays / dueAt / reviews / status`。

- 分数用移动平均（答对拉向 100、部分拉向 60、答错拉向 0），避免一次发挥定生死。
- 置信度 = 证据广度 × 是否跨天 × 时效。
- 间隔复习用简化 SM-2：答对拉长间隔，答错打回 1 天。
- 错误类型单独计数，`dominantError` 进系统提示，让模型知道这个学生常错在哪一类。
- 复习：`tutorflow_progress({action:'review'})` 取最该复习的一条，只抽一道题。

### 9. 模型能力差异

- 系统提示段本身是**完整教学法**，即使模型一次工具都不调，也能按它教。
- `preferences.modelTier`（small / standard / strong）：small 档下引擎承担对错判定与路线，
  `constraints.needsVerdict=false`、`allowPlan=false`，指令里直接写明「照这一条做即可」。
- 所有工具参数都有默认值；路线、判定、错误类型、图形参数缺省时都能退化成可用状态。

### 10. 为什么这不是一段长提示词

提示词只负责「方法」；以下是提示词做不到、必须由插件承担的：

- **状态**：跨轮、跨会话的路线游标、证据计数、表征游标、复习排期。
- **约束**：只问一个问题的机械保证（`normalizeQuestion` + 一次一问的构造），不是靠模型自觉。
- **判定**：错误分型 → 动作的确定性映射，以及「模型不给判定就不放行」的兜底。
- **记忆**：跨会话的置信度与间隔复习。
- **产物**：本地 SVG 图与 data URI，不依赖任何外部渲染。

### 验收自问

> 明天用户问一个插件从未预设过的知识点，它还能不能像一位优秀私人教师那样教？

能。因为「教」需要的那套形状——定位、拆步、一次一问、换讲法、分型、检验、记忆——全部与内容解耦，
并且在 `test/tutorflow.test.mjs` 里用七个学科、零课程包的场景逐条断言。
